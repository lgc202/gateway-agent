# 聊天与消息实施计划

> 状态：已完成
> 完成日期：2026-07-21
> **执行要求：** 直接在 `main` 工作，不创建分支或 worktree，不自动提交，不编写 `*_test.go`。执行过程中用户允许使用子 Agent，因此只将互不冲突的实现与审查任务委派出去，最终结果由主 Agent 统一验证。

**目标：** 将当前 PostgreSQL 原型替换为可真实运行的 MySQL 8.4 Chat/Message API，只实现 03 文档已经确认的两张表和四个 HTTP 接口。

**架构：** 保持 Gin Handler、Chat Service、MySQL Store 三层。Store 使用 `database/sql + go-sql-driver/mysql + sqlc`，Service 负责 Message 写入事务，所有 HTTP JSON 响应统一为 `code`、`message`、`data` 三个字段。

**技术栈：** Go 1.26.x、Gin v1.12.0、Google Wire v0.7.0、MySQL 8.4、go-sql-driver/mysql v1.10.0、Viper v1.20.1、sqlc、golang-migrate、OpenAPI 3.1、Docker Compose。

**依据文档：**

- [02-网关智能体目标产品与架构设计](./02-网关智能体目标产品与架构设计.md)
- [03-聊天与消息基础设计](./03-聊天与消息基础设计.md)

```go
type Config struct {

```

- [x] 默认读取 `configs/gateway-agent-apiserver.yaml`。

- [x] `HTTP_HOST`、`HTTP_PORT` 分别覆盖 `http.host`、`http.port`。
- [x] `MYSQL_HOST`、`MYSQL_PORT`、`MYSQL_DATABASE`、`MYSQL_USERNAME`、`MYSQL_PASSWORD` 分别覆盖 `mysql` 下的同名字段。
- [x] HTTP Host、Port 和 MySQL Host、Port、Database、Username、Password 缺失或 Port 非法时启动失败。
- [x] HTTP Server 使用 `net.JoinHostPort` 根据 `http.host` 和 `http.port` 生成监听地址。
- [x] 不实现配置热更新、远程配置中心和多环境继承。

### 5.2 Store

- [x] `Store` 保存 `*sql.DB` 和 `*sqlc.Queries`。
- [x] `NewDB` 使用 MySQL Driver 的 `NewConfig` 和 `FormatDSN` 生成 DSN，固定使用 TCP、`parseTime=true`、UTC、`utf8mb4` 和 `utf8mb4_0900_ai_ci`，启动时 `PingContext`。
- [x] MySQL Driver 固定连接超时 5 秒、读写超时各 10 秒，不新增配置项。
- [x] 设置有限连接池：最大打开 20、最大空闲 10、连接最大生命周期 30 分钟、空闲时间 5 分钟。
- [x] Store 提供 `WithinTransaction`，使用 `sql.TxOptions{Isolation: sql.LevelReadCommitted}`。
- [x] 事务回调失败时 Rollback，成功时 Commit，Commit 错误必须返回。
- [x] Chat 业务数据库操作和事务固定最长 10 秒，并保留调用方更早的 deadline。
- [x] 数据库错误默认映射为 `INTERNAL_ERROR`；仅连接、超时和明确的 MySQL 瞬态错误（包含 Begin/Commit 以及 Driver `ErrInvalidConn`）映射为 `DEPENDENCY_UNAVAILABLE`，底层原因仅供服务端日志。

### 5.3 Chat Store 方法

- [x] `CreateChat`：执行 `InsertChat`、读取 `LastInsertId`、调用 `GetChat`。
- [x] `GetChat`：将 `sql.ErrNoRows` 映射为 `CHAT_NOT_FOUND`。
- [x] `AppendMessage` 在一个事务中完成：

```text
GetChatForUpdate
InsertChatMessage
TouchChat
GetChatMessage
Commit
```

- [x] `GetChatForUpdate` 查不到记录时映射为 `CHAT_NOT_FOUND`。
- [x] `GetChatForUpdate` 在分配 Message ID 前锁定 Chat 行，使同一 Chat 的 ID 分配顺序与提交顺序一致，防止客户端推进 `after_id` 后漏消息；不同 Chat 仍可并发写入。
- [x] `TouchChat` 单调递增 `updated_at`，避免同微秒写入因 `RowsAffected=0` 被误判为失败；返回影响行数不是 1 时仍返回内部错误。
- [x] `ListMessages` 调用游标查询，空结果必须返回空 Slice。

Store 不定义只有一个实现的接口，不暴露 sqlc Model 给 Handler。
