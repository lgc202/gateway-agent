## 推荐阅读顺序

### 1. 产品需求

[01-企业级AI网关运维智能体产品需求文档.md](./01-企业级AI网关运维智能体产品需求文档.md)

从客户、用户和高级产品经理视角说明为什么需要 Gateway Agent、要解决哪些问题，以及审批和执行体验应该是什么样。

原文末尾保留的 Slice 路线属于早期讨论记录，不再决定实现顺序和技术边界。当前产品边界以 02 文档为准。

### 2. 目标产品与架构设计

[02-网关智能体目标产品与架构设计.md](./02-网关智能体目标产品与架构设计.md)

这是产品边界、总体架构和长期技术方向的权威基线。它回答“整个 Gateway Agent 最终是什么”，包括单 Gateway 部署边界、MySQL、Redis、Temporal、Qdrant、Eino、Tool、Skill、MCP 和审批原则。

### 3. 聊天与消息基础设计

[03-聊天与消息基础设计.md](./03-聊天与消息基础设计.md)

这是已经完成的第一份详细设计，解释 Chat 和 Message 的基础模型。它对应项目当前已经运行的 Chat/Message HTTP API。

03 记录的是“基础实现当时如何建立”，不是下一步目标 Schema。涉及 Task、Run、Task Input、Event、Outbox 以及 chat_messages.task_id 时，以 05 文档为准。

### 4. 聊天与消息实施记录

[04-聊天与消息实施计划.md](./04-聊天与消息实施计划.md)

这是 03 设计对应的已执行文件级计划，用来追踪 MySQL、sqlc、Chat/Message HTTP API 和真实运行验证如何落地。

### 5. 输入规范化与可靠执行设计

[05-输入规范化与可靠执行设计.md](./05-输入规范化与可靠执行设计.md)

这是当前第二个详细设计，也是 Task、Agent Run、Task Input、Task Event、Temporal、Outbox、Redis Streams、Redis Pub/Sub 和 Chat SSE 的权威说明。

当前状态：设计和 06 文件级实施计划均已审查确认，等待逐 Task 实施。当前闭环只实施 MySQL Event、Redis Pub/Sub 和 Chat SSE，Redis Streams 等模型流式回复能力按 05 中的未来边界另行启动。

建议初学者完整阅读。文档用“配置一条网关路由”的例子贯穿全部概念，并专门解释：

- Chat、Task、Run 分别是什么；
- 为什么一条用户消息对应一个 Run；
- Eino Graph、ChatModelAgent、ReAct、Tool、Callback、Streaming 是什么；
- Eino 与 Temporal 为什么同时存在；
- Outbox 为什么只负责可靠唤醒 Temporal；
- MySQL、Redis Pub/Sub、Redis Streams 各自保存什么；
- 为什么整个 Chat 只维持一条 SSE，Run 结束时不关闭；
- Redis 故障、浏览器断线、Worker 重启时如何恢复。

### 6. 输入规范化与可靠执行实施计划

[06-输入规范化与可靠执行实施计划.md](./06-输入规范化与可靠执行实施计划.md)

这是 05 经确认后的文件级执行计划。它把当前闭环拆成可逐个审查、逐个运行和逐个提交的 Task，并明确不写测试、不做无意义防御、不创建未来空实现。

实施时先读对应 Task，再查看 05 中的设计原因；不得只看文件列表跳过事务、恢复和验证步骤。

## 当前权威关系

```text
01 产品需求
    ↓
02 总体产品与架构基线
    ↓
03/04 已完成的聊天基础设计与实施记录
    ↓
05 当前详细设计：输入规范化与可靠执行
    ↓
06 当前实施计划：按 Task 小步落地
```

若文档间出现细节冲突：

1. 当前详细设计优先于已完成的基础实施记录；
2. 05 中 Task/Run/Temporal/Redis/SSE 的细节优先于 02 中的概括描述；
3. 06 只能细化 05，不能改变 05 的业务和可靠性边界；
4. 02 中产品边界和长期技术决策仍然有效；
5. archive 下的历史文档永远不作为实现依据。

## 文档维护规则

1. 当前有效文档使用 00-89 编号；
2. 历史文档使用 90-99 编号并放入 archive/；
3. 文件名使用中文，必要的产品名和技术名保留英文；
4. 新增文档前先更新本阅读指南；
5. 架构决策发生变化时，先修订目标设计，再修改代码；
6. 流程、时序和状态变化优先使用 Mermaid；
7. AI 生成的产品概念图和架构总览图保存在 assets/；
8. AI 插图用于帮助理解，不作为字段、接口和时序的精确实现依据；
9. 不再使用 Slice 1A、core tables 等无法长期表达职责的名称。
