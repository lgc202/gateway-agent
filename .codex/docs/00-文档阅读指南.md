# 00 文档阅读指南

## 1. 这套文档解决什么问题

Gateway Agent 的代码和设计都在持续演进。主文档目录只描述两类内容：

1. 当前代码已经具备、可以从仓库中找到实现的能力；
2. 已经明确的产品边界和下一步设计原则。

已经撤销的 Task、Run、Worker、Temporal、Redis Stream、Outbox 等方案不再保留在主文档中。需要了解历史时直接查看 Git 历史，不维护第二套容易误导读者的历史文档。

## 2. 推荐阅读顺序

### [01 企业级 AI 网关运维智能体产品需求文档](./01-企业级AI网关运维智能体产品需求文档.md)

从客户和产品视角回答：

- 为什么需要 Gateway Agent；
- 当前解决哪一个真实问题；
- 用户如何查询路由、发起创建并完成审批；
- 哪些能力已经实现，哪些没有实现；
- 产品验收时应该看什么。

第一次了解项目，从这里开始。

### [02 系统架构设计](./02-系统架构设计.md)

从工程视角说明当前真实系统：

- 为什么现在只有一个 `chat-svc`；
- Gin、Service、Store、Eino、MySQL 和 Higress 如何协作；
- 请求、模型流、Tool 调用和持久化如何流动；
- 为什么当前没有 Redis、Temporal、Qdrant 和独立 Worker；
- 后续扩展时必须保持哪些边界。

### [03 接口与数据模型](./03-接口与数据模型.md)

用于开发前端、联调接口和理解数据库：

- 当前全部 HTTP API；
- 普通 JSON 响应与 SSE 响应的区别；
- SSE 的三个业务事件；
- `chats`、`chat_messages`、`model_configs`、`approvals` 四张表；
- 配置文件与环境变量。

精确的机器可读接口契约以 [`api/openapi/gateway-agent.v1.yaml`](../../api/openapi/gateway-agent.v1.yaml) 为准。

### [04 Agent 运行与工具设计](./04-Agent运行与工具设计.md)

面向第一次接触 Agent/Eino 的开发者，解释：

- Agent、Runner、ReAct、Tool 分别是什么；
- 为什么代码中既有 `iterator.Next()`，又有 `stream.Recv()`；
- 模型配置如何变成 Eino 模型实例；
- `query_routes` 与 `create_route` 如何注册和执行；
- 当前上下文管理做到哪一步。

### [05 路由审批与恢复设计](./05-路由审批与恢复设计.md)

详细说明当前最关键的安全链路：

- 为什么写 Tool 必须中断；
- Approval 和 Checkpoint 分别保存什么；
- 用户批准或拒绝后如何恢复原调用；
- 审批状态为什么不等于执行状态；
- 前端如何在对话中展示审批卡片。

### [06 未实现能力与实现原则](./06-未实现能力与实现原则.md)

这是后续设计和开发的长期检查清单，记录：

- 当前还没有实现的能力；
- 什么真实问题出现后才应该实现；
- 每项能力的最低验收条件；
- 应优先复用或参考哪些开源实现；
- 哪些组件和概念当前明确不应提前引入。

准备增加新能力前，先阅读这一篇。它不是按阶段承诺功能的路线图。

## 3. 文档中的状态词

为避免把愿景写成现状，本文档统一使用下面三种表述：

| 表述 | 含义 |
|---|---|
| 已实现 | 仓库中存在调用方和可运行代码 |
| 已确定边界 | 设计方向已经明确，但还没有实现 |
| 未设计 | 需求存在，但实现方式还需要结合真实用例讨论 |

“将支持”“可以扩展”“目标是”都不表示代码已经存在。

## 4. 当前能力一览

| 能力 | 状态 | 代码位置 |
|---|---|---|
| Chat 与 Message | 已实现 | `internal/chatsvc/service/chat` |
| 模型配置 CRUD | 已实现 | `internal/chatsvc/service/modelconfig` |
| 多模型 Provider | 已实现 | `internal/chatsvc/service/agent/model.go` |
| Eino Agent 流式回复 | 已实现 | `internal/chatsvc/service/agent` |
| Higress 路由查询 | 已实现 | `internal/chatsvc/service/agent/tool/route_query.go` |
| 创建路由审批 | 已实现 | `internal/chatsvc/service/agent/tool/route_create.go` |
| Approval 持久化与恢复 | 已实现 | `internal/chatsvc/service/chat/approval.go` |
| 输入规范化 | 仅有 Tool 参数级校验 | 尚无独立用户需求规范化器 |
| 意图识别 | 未独立实现 | 当前由模型在 ReAct 中选择 Tool |
| 上下文压缩与长期召回 | 未实现 | 当前只读取最近 100 条消息 |
| Plan/Replan | 未实现 | 当前审批绑定 Tool 参数 |
| Skill/MCP | 未实现 | 不保留空接口 |
| 身份、RBAC、审计 | 未实现 | 接入企业环境前必须设计 |
| OpenTelemetry/Prometheus | 未实现 | 后续按真实运维指标接入 |

## 5. 事实来源优先级

发现文档和代码不一致时，按以下顺序判断：

1. 当前 `main` 分支代码和 Migration；
2. OpenAPI；
3. 02～05 当前设计文档；
4. 06 未实现能力与实现原则；
5. 01 产品需求；
6. Git 历史中的旧文档和讨论记录。

发现不一致后应直接修正文档，不新增“临时说明”或兼容旧术语。
