# Gateway Agent 文档阅读指南

> 更新时间：2026-07-21
> 这份文件是 `.codex/docs` 的统一入口。

## 推荐阅读顺序

### 1. 产品需求

[01-企业级AI网关运维智能体产品需求文档.md](./01-企业级AI网关运维智能体产品需求文档.md)

从客户、用户和产品经理视角说明为什么需要 Gateway Agent、要解决哪些问题、审批和执行体验应该是什么样。

原文末尾保留的 Slice 路线属于早期讨论记录，不再决定实现顺序和技术边界。当前产品边界以 02 文档为准。

### 2. 目标产品与架构设计

[02-网关智能体目标产品与架构设计.md](./02-网关智能体目标产品与架构设计.md)

这是当前唯一的权威技术设计，后续数据模型、代码结构和实施计划都必须服从该文档。

已经确认的核心边界：

- 一套 Gateway Agent 绑定一套逻辑 Gateway；
- 不做共享数据库多租户和 Gateway Fleet 管理；
- 保留输入规范化、意图识别、上下文、检索、Plan、Replan、TAO、ReAct；
- 保留 Tool、Skill 和 MCP，但不建设对应的数据库管理平台；
- MySQL 是业务事实来源；
- Redis、Temporal 和 Qdrant 各自承担明确职责；
- 审批在对话中展示，审批决定通过 HTTP 提交；
- 后续实现不再采用会被推翻的临时架构。

### 3. 聊天与消息基础设计

[03-聊天与消息基础设计.md](./03-聊天与消息基础设计.md)

这是当前第一个进入详细字段设计的业务用例，只创建 `chats` 和 `chat_messages`。Agent Run、Event、Approval、Outbox 等对象等真正使用时再设计。

### 4. 聊天与消息实施计划

[04-聊天与消息实施计划.md](./04-聊天与消息实施计划.md)

在 03 设计确认后执行的文件级计划，范围只包含 MySQL、sqlc、Chat/Message HTTP API 和真实运行验证。

## 文档维护规则

1. 当前有效文档使用 `00-89` 编号；
2. 历史文档使用 `90-99` 编号并放入 `archive/`；
3. 文件名使用中文，必要的产品名和技术名保留英文；
4. 新增文档前先更新本阅读指南；
5. 架构决策发生变化时，先修订目标设计，再修改代码；
6. 流程和时序优先使用 Mermaid；
7. 产品概念图和架构总览图保存在 `assets/`；
8. 不再使用 `Slice 1A`、`core tables` 等无法长期表达职责的名称。
